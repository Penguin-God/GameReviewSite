# 여백 — 나의 기록 공간

`새 기획.txt`와 `구현 단계.txt`의 1·2단계를 구현한 React + TypeScript + Vite 앱입니다. 개인 글과 폴더는 브라우저에, 명시적으로 공유한 글의 사본은 자체 Node.js + SQLite 서버에 저장합니다.

## 실행

Node.js 22.19 이상을 사용합니다.

```sh
cd Assets
npm install
npm run dev
```

위 명령 하나로 화면(기본 `http://127.0.0.1:5173`)과 공유 API(기본 8787 포트)를 함께 실행합니다. 터미널에서 **Ctrl + C**를 누르면 둘 다 종료합니다. 기존 글이 `localhost:5173`에 있었다면 같은 주소로 접속해야 보입니다. `localhost`와 `127.0.0.1`은 브라우저 저장 공간이 다릅니다.

```sh
npm run build
npm run lint
npm run test -- --run
npm run test:server
```

## 글과 폴더

- 일반 텍스트 제목·본문으로 여러 글을 작성하고 자동/수동 임시 저장합니다. Ctrl/Cmd + S도 지원합니다.
- 새 폴더를 만들고, 편집기의 폴더 선택으로 글을 이동합니다. 공유 여부와 관계없이 같은 방식으로 분류합니다.
- 왼쪽 목록에서 모든 글·미분류·각 폴더를 볼 수 있습니다. 선택한 폴더에서 새 글을 만들면 그 폴더에 저장합니다.
- 폴더 이름 변경과 삭제를 지원합니다. 폴더를 삭제해도 글은 **미분류로 이동**하고 남아 있습니다.
- 글 삭제는 확인 창을 거칩니다. 공유한 글은 서버의 링크를 먼저 중단한 뒤 개인 기록을 삭제합니다. 서버 연결에 실패하면 공유 중인 글의 삭제를 중단하고 재시도를 안내합니다.
- 기존 1단계 기록은 같은 `yeobaek.drafts.v1` 키에서 읽어 본문·ID·시각을 보존하고 미분류로 이전합니다. 저장 문서의 내부 버전만 2로 올립니다.
- 저장 실패, 손상된 데이터, 다른 탭의 변경을 감지합니다. 실패한 입력을 화면에 유지하고 재시도를 제공합니다. 여러 탭의 동시 쓰기를 원자적으로 잠그지는 않으므로 한 탭에서 작성하는 것을 권장합니다.

## 공유

1. 글에서 **공유하기 → 공유 링크 만들기**를 선택합니다.
2. **링크 복사**로 주소를 전달합니다. `/share/:id` 페이지는 제목·본문만 보여주는 읽기 전용 화면입니다.
3. 개인 글을 수정해도 공개된 내용은 자동 변경되지 않습니다. **공유 관리 → 공유 내용 업데이트**로 반영합니다.
4. **공유 중단** 또는 글 삭제 후에는 기존 링크로 읽을 수 없습니다. 다시 공유하면 새 주소를 발급합니다.

독자는 로그인 없이 링크를 읽을 수 있습니다. 전체 공유 글을 나열하는 API는 없고, 폴더·개인 글 목록도 보내지 않습니다. HTML/Markdown 문자열은 렌더링하지 않고 일반 텍스트로 보여줍니다.

공유 ID와 별도로 무작위 관리 토큰을 생성합니다. 관리 토큰은 작성자 브라우저에만 저장하고 서버에는 해시를 보관합니다. 읽기 API는 토큰을 반환하지 않으며, 수정·중단에는 해당 토큰이 필요합니다. 서버 응답이 유실되더라도 관리할 수 있게 토큰을 먼저 브라우저에 저장합니다. 중단 시 공개 본문을 비우고 링크 ID와 토큰 해시를 남겨 지연된 요청이 링크를 다시 살리지 못하게 합니다.

공유 요청은 JSON 기준 1MB까지, 쓰기 요청은 연결 IP별 분당 120회로 제한합니다. 공유 페이지에는 검색 색인 방지 지시와 캐시 방지 헤더를 적용하지만, 링크를 받은 사람이 이미 읽거나 복사한 내용까지 회수할 수는 없습니다.

## 저장 범위

| 데이터 | 저장 위치 |
| --- | --- |
| 개인 글 원본, 폴더, 공유 관리 토큰 | 현재 브라우저의 localStorage |
| 공유 시점의 제목·본문·시각, 관리 토큰 해시 | `Assets/data/shared-posts.sqlite` |
| 다른 사람의 읽기 화면 | 공유 API에서 해당 글만 조회 |

서버를 껐다 켜도 SQLite 파일이 남아 있으면 공유한 글은 유지됩니다. 개인 기록과 관리 토큰은 계정 동기화가 없으므로 브라우저 사이트 데이터를 삭제하면 사라집니다. **브라우저 데이터를 지우기 전에 공유 중인 글을 중단해야** 관리할 수 없는 공유 링크가 남지 않습니다. 같은 브라우저 프로필을 사용하는 사람끼리는 개인 글이 분리되지 않습니다.

조회수와 계정·개인 글의 서버 동기화는 이번 2단계 범위에 포함하지 않았습니다. 기존 Supabase DB는 사용하거나 변경하지 않습니다.

## 실제 배포

현재 로컬 주소는 다른 사람의 컴퓨터에서 열 수 없습니다. 외부 공유에는 Node.js 서버와 영속적인 디스크가 있는 호스팅이 필요합니다. 프런트엔드 파일만 정적으로 배포하면 공유 API는 동작하지 않습니다.

```sh
npm run build
npm start
```

`npm start`는 같은 서버에서 빌드된 `dist` 화면, 공유 페이지, API를 제공합니다.

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 호스팅에서 외부 요청을 받으려면 배포 환경에 맞게 `0.0.0.0` 등으로 설정 |
| `PORT` | `8787` | 운영 서버 포트 |
| `DATABASE_PATH` | `Assets/data/shared-posts.sqlite` | 영속 디스크의 SQLite 파일 경로 |
| `PUBLIC_ORIGIN` | 없음 | 배포 주소 예: `https://journal.example.com` (끝의 슬래시 제외) |
| `API_PORT` | `8787` | 개발/preview 프록시용 API 포트 |

운영 환경에는 HTTPS와 `PUBLIC_ORIGIN`을 설정합니다. 프록시를 사용한다면 외부 사이트 주소를 정확히 설정해야 출처 검사가 통과합니다. DB 파일과 WAL 파일이 있는 디렉터리를 영속 디스크에 두고, 백업 시에는 서버를 정상 종료한 뒤 복사하거나 SQLite 백업 도구를 사용합니다. `data/`는 Git에서 제외합니다.

이 저장소는 [Node.js의 내장 SQLite API](https://nodejs.org/download/release/v22.19.0/docs/api/sqlite.html)를 사용합니다. Node.js 22에서는 실험 기능 경고가 출력될 수 있습니다.
